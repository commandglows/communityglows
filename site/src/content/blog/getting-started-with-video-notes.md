Your first useful workspace does not need every network. Start with one profile, one account and one concrete action. This guide takes you from installation to a repeatable routine, then explains the tools you can add as you become comfortable.

This is the **Windows launch guide**. Check the [download page](/download) and the release notes for the version you install. Android and browser extensions have different capabilities and are not presented here as public launch downloads. Features described below reflect the implemented product; a newer interface or option may still be awaiting inclusion in your installer.

## 1. Install and open the application

Open the [Windows download page](/download), follow its release link and choose the Windows installer listed in that release. Read the release notes before installing, especially when updating an existing workspace. Launch CommunityGlows after installation.

If Windows prevents installation, record the exact message and check the installer source. Do not disable system protection to work around an unexplained warning. The [help page](/help) explains how to report it.

At the account screen, create a CommunityGlows account or sign in with your existing one. This account organizes your application data and cloud synchronization. It is **not** a login to Instagram, LinkedIn or another social network. Access and purchase conditions are shown on the [pricing page](/pricing); downloading the installer alone does not prove that a trial or purchase has been activated.

## 2. Create your first profile

Use the profile controls in the sidebar to create a clearly named workspace, such as “Personal” or “Client — Studio”. Give each context a recognizable name or appearance so you can identify it before acting.

Choose one network for this first profile. Open it and complete that platform’s own sign-in, including any two-factor authentication or captcha. Check the account avatar and name inside the network before sending a message or publishing anything.

Next, create a second profile if you need another account on the same network. Sign in separately and verify which identity appears when switching profiles. Profile separation helps organize sessions; it does not guarantee anonymity, remove platform restrictions or replace your own identity check. See [the account separation guide](/blog/separate-multiple-social-accounts-on-one-device).

## 3. Keep only useful networks and links

Use the network visibility controls to keep your sidebar focused on the active profile. A visible network is an entry point to that service, not evidence that all its features work inside an embedded browser.

Add custom links for an external tool or a specific destination you use repeatedly. Choose a recognizable name and check the address before saving. Test the link once, in the intended profile, before relying on it in your routine.

If a platform refuses to sign in or displays an unsupported-browser message, check whether the same account works in your usual browser. Some authentication flows cannot run inside an embedded view. Opening a site elsewhere does not copy that browser’s cookies into CommunityGlows. Read [social platform limitations](/blog/social-platform-limits-communityglows) for the boundaries.

## 4. Try Bento and save a Scene when available

Bento is the desktop workspace for viewing several network panels together. Open two useful networks, arrange the panels, and resize them to match the task. For example, keep a discussion next to the page you are reviewing. Start small: every open site can consume memory and continue background work.

A named Scene records an arrangement you want to reuse. It belongs to a profile and restores the organization of its panels, not a new login to each platform. Your current unsaved arrangement is a local draft.

**Version check:** Bento refinements, including newer layout presets and task panels inside the cockpit, are still being prepared for release. Do not assume that an option shown in a development article is in your installed version. Use the controls actually present and consult its release notes. The [Bento article](/blog/turn-large-screen-into-multi-network-cockpit-bento) explains the concept in depth.

## 5. Capture the next action in Tasks

Open **Tasks** to record an action you intend to perform yourself. A useful first example is “Reply to Alex about the launch”, with a context link and a due date.

Add the people, notes, tags, priority and supporting links that help you resume the task later. Move it through the available stages as your work progresses. The task board is an organizer: creating a task does not send a message, schedule a social post or scrape a conversation.

Tasks use local storage and participate in workspace cloud synchronization when connected. Before relying on a task from another device, verify that synchronization has completed and that the other app version supports it. Avoid using the board as the only record of something you cannot afford to lose.

## 6. Adjust focus and keyboard controls

Open Settings and try one comfort control at a time: theme, grayscale, sound or text zoom where available. A site may render some elements differently or handle sound itself, so verify the result on the actual page you use.

The keyboard shortcuts settings list the current assignments and let you change or disable them. Assign one shortcut for a frequent action, try it with focus in the application interface, then try it inside a social page. Embedded pages can capture keystrokes themselves; a shortcut that works in the sidebar may behave differently while typing in a site.

## 7. Understand synchronization and backups

Cloud synchronization can carry supported application data such as profiles, preferences, custom links, named Scenes and task state. It does not move your signed-in social sessions or a password-manager vault to another computer. Expect to authenticate to each network again on a new device.

A backup is a separate operation. In the native backup controls, export a backup file, protect it with a password and store the file somewhere you can recover. Keep that password separately. Restoring a backup can replace application data and affect synchronized state; make a fresh export before restoring and read the dialog carefully.

Neither a Scene nor a successful local save proves that a backup contains every current feature. Consult [what stays local and what syncs](/blog/what-stays-local-and-what-syncs-in-communityglows) before migrating or resetting a device.

## 8. Rehearse your everyday routine

Before using the app for important work, complete this short rehearsal:

- Open the intended profile and confirm the identity inside the network.
- Open a saved link and record one task with its context.
- Switch profiles and check that the account context is the one you expect.
- Close and reopen the app to check what your installed version restores.
- Find the backup controls and the help page before you need them.

If a page becomes slow, reduce the number of open networks and retry the same action. If a session expires, sign in again through the platform’s own screen. If a feature is missing, compare your installed version with its release notes before resetting data.

For a report, include the app version, Windows version, affected network, steps and exact error text. Remove private messages, cookies, tokens and passwords from any screenshot. Use the [help and troubleshooting centre](/help#contact) for the next step.
