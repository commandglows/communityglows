# Bug Record: BUG-2026-08-08-003

## Summary

- Title: Windows password sign-in reloads before Convex confirms the session
- Current status: `fix-attempted`
- Severity: `high`
- Owner: Diane
- Next command: `/sg-test --retest BUG-2026-08-08-003 on Windows package`

## Reproduction

- Preconditions:
  - Fresh signed-out Windows Tauri session with Convex configured.
- Steps:
  1. Open the account login screen.
  2. Submit valid email/password credentials.
  3. Observe the sync overlay flash and the app return to login.

## Expected Behavior

- Convex confirms the JWT on the realtime client, cloud data hydrates, then the authenticated app opens.

## Observed Behavior

- Tokens are persisted optimistically, cloud hydration can see no authenticated user and return silently, then the app reloads into `signed_out`.

## Evidence

- Build `31267734804`, commit `9358553`, `convex_configured: yes`, `account_state: signed_out`, no recent auth events.
- Android settings authentication succeeds because it commonly reuses an already initialized client; Windows fresh login exposes the bootstrap race.
