# BUG-2026-09-07-001

## Summary

The public local Kanban must render inside the application shell like other content. Its isolated guest task storage and existing protected route guards are unchanged.

## Reproduction

Complete onboarding through the actual UI at the managed local server on port 3006, then navigate to `#/local-kanban`. Before repair the task board rendered but `.desktop-layout` count was zero.

## Expected Behavior

Desktop sidebars and navigation remain visible. Mobile keeps its header, settings access, and profile bar. Tasks persist locally and navigation to another surface remains possible.

## Observed Behavior

The root App.vue conditional selected a standalone TasksView before either desktop or mobile layout, removing all surrounding navigation.

## Diagnosis Notes

2026-09-07 UTC: Root conditional bypass confirmed by code and live browser reproduction. The route already supplies `localOnly: true`, so a separate top-level TasksView is unnecessary. MobileLayout lacked a route outlet for this surface.

## Fix Attempts

2026-09-07 UTC: Removed standalone root branch/import. Local route entry clears the active network and closes Bento so the normal desktop route outlet renders the board. The existing local access exemption applies only while no network/Bento is selected. Mobile displays the route in the existing content scroll area. No token, styling, auth, store, or network service changes.

Mobile 420x850 keeps header/settings/profile bar, without overflow; settings opens successfully. Root agent inspected rendered screenshots. No page console errors after reload. Native Windows app not exercised.

Focused Vitest run: desktopSurface.test.ts, guards.local.test.ts, localTasks.test.ts: 3 files / 9 tests passed. These cover existing selection, public/guarded route separation, and isolated local persistence; live UI scenarios supply regression proof for shell placement.
