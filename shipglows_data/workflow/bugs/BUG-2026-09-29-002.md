# Bug Record: BUG-2026-09-29-002

## Summary

Diane installed candidate `37495179e44d784907ad0c978bf617499faa699c` and reported that it connects but skips the existing onboarding: no language choice first, no clear account creation offer and no explanation of whether a trial was granted. The reported connection is separate from precise authenticated entitlement proof. The user requires reuse of existing mechanisms and controls.

## Reproduction

1. Keep existing local/cloud `onboarding.completed=true` and a previous locale/session.
2. Start the previous candidate or reload the real browser at `http://127.0.0.1:3016` with its existing state.
3. Observe the login/workspace path without a deliberate language choice or the required account/access explanation.

Root reproduced the browser entry directly at `/login` in English before the patch. A fresh browser origin was also used for the patched path; no credentials were submitted or identity injected.

## Expected Behavior

- Ask for language first for the corrected journey, including legacy completed/restored state.
- Reuse `OnboardingFlow.vue` for welcome, profile, networks and features; preserve existing preferences when replaying/skipping untouched steps.
- Offer the existing `LoginView.vue` creation/sign-in form clearly. A restored identified account can continue or change; a restored anonymous session is identified as such and can still create/sign in.
- Reuse `BillingAccessPanel.vue` before protected work, displaying only actual backend trial/license state and dates. Unknown availability is an error/retry state, not a missing/free trial or a reason to buy.
- Preserve session confirmation, session lock, server entitlements, native WebView gates and isolated local tasks.
- Keep a completed journey complete on normal launches of the same installation/build; replay it from language after an intentional app build/update or installer reinstall, and preserve the Settings replay action.
- Keep onboarding lifecycle markers local to the surface and out of account sync/portable backups. Do not reset billing installation identity, trial, profiles or user data to replay onboarding.

## Security And Coverage

- Server auth, entitlement/trial/restart policy, schema, Google OAuth and payment/email providers are unchanged. No token, profile or network purge, no fabricated grant, no trial reset and no fake free/access state.
- Local journey markers: `selectedLanguage`, `setupCompleted`, `accountConfirmed`, `confirmedAccountId`, `localOnly`, `accessConfirmed`, `completionVersion=1`. The legacy cloud `completed` flag cannot acknowledge this journey. Current hydrated identity must match `confirmedAccountId` before protected work/preload; changing account resets only account/access acknowledgement.
- Auth bootstrap and session-lock remain authoritative. No native network preload while language, account/access, session or lock is pending. Existing local Kanban remains isolated; its disclosure grants nothing.
- Account choices/submit wait for active hydration, then recover on terminal failure. Hydration and billing responses from previous sessions cannot apply to the new identity or clear a new pending operation's flags. Existing cloud queue/seed implementation is retained.
- Existing locale chosen later in Settings survives reopening/account reset; an in-progress local language choice is not replaced by legacy cloud preferences.
- Journey scope is `{installation, build}`. NSIS/MSI use a random file witness beside the executable; reinstall/update replaces only that file, and normal launch/replay does not change the entitlement installation key. Chrome/Firefox use their existing install/update event. Web/dev and non-Windows native targets use build scope but have no proven same-package reinstall signal.
- OWASP A01/A07/A10: identity, authorization and async error boundaries are preserved and exercised. ZOMBIES: old/new state, restored anonymous/identified accounts, replay/skip, loading/error/grace, account switch and late async response.
- Fresh primary references: `https://vuejs.org/guide/essentials/watchers.html`, `https://pinia.vuejs.org/core-concepts/getters.html`, `https://prazdevs.github.io/pinia-plugin-persistedstate/guide/config.html`. Canonical design tokens and existing UI primitives are reused.
- Candidate-only checkpoint is explicitly authorized for private Windows acceptance; draft PR #67 stays isolated. The full Vue typecheck failure and pending native/authenticated proof remain visible. No main merge, backend deployment, public installer promotion or ready-for-production claim.
