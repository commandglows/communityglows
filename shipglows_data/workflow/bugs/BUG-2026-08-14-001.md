# Bug Record: BUG-2026-08-14-001

## Summary

- Title: Android debug build rejects the weighted `Typeface` overload
- Current status: `fix-attempted`
- Severity: `high`
- Owner: Diane
- Next command: rerun the Android arm64 debug workflow on the repair commit

## Reproduction

- Preconditions:
  - Build the Android plugin with `minSdk = 24` and `compileSdk = 35`.
  - Use the source published at commit `6a2e172b6fc69862f555a2b0addb760a0a05ce44`.
- Steps:
  1. Run `pnpm exec tauri android build --ci --debug --apk -t aarch64` in GitHub Actions.
  2. Allow the generated Android project to compile `tauri-plugin-android-webview`.
  3. Observe Kotlin compilation at `NativeWebViewPlugin.kt:522`.

## Expected Behavior

- Kotlin compilation selects an API-compatible `Typeface` overload.
- Android 28 and later use the configured numeric weight.
- Android 24 through 27 use the configured `sans-serif-medium` family with normal style.

## Observed Behavior

- Kotlin selects the API-28 weighted overload whose first parameter is `Typeface?`, but the code supplies a `String` family name.
- `:tauri-plugin-android-webview:compileDebugKotlin` fails with `Type mismatch: inferred type is String but Typeface? was expected` and no APK is produced.

## Evidence

- Hosted reproduction: `https://github.com/commandglows/communityglows/actions/runs/31845821918`
- Redacted compiler excerpt: `NativeWebViewPlugin.kt:522:9 Type mismatch: inferred type is String but Typeface? was expected`.
