# Bug Record: BUG-2026-09-29-001

## Summary

Windows network WebViews overlap the left sidebar and leave empty space to the right and bottom when the shell is zoomed. Status: `fix-attempted`; rendered retest remains required.

## Reproduction

1. Open CommunityGlows Windows with UI scale at 130%.
2. Open X, Facebook or TikTok from the sidebar.
3. Resize the window and change networks.

Expected: the child WebView exactly fills its measured host, including after zoom, resize, pooled restore and monitor DPI changes. Network text zoom remains independent.

Observed: screenshots show native x=268 and width=840 where the rendered host starts near x=348 and spans about 1092 pixels. A native runtime screenshot reproduced TikTok starting x=200 while the sidebar ends x=260.

## Evidence

- Four operator screenshots attached to the 2026-09-29 repair conversation; no private session data copied into this record.
- `uiScale.ts` applies native main-WebView `setZoom`; DOM CSS bounds were sent directly to Rust `LogicalPosition` / `LogicalSize`.
- [MDN devicePixelRatio](https://developer.mozilla.org/en-US/docs/Web/API/Window/devicePixelRatio): browser DPR includes page zoom.
- [Tauri DPI API](https://v2.tauri.app/reference/javascript/api/namespacedpi/): logical and physical units are related by the native window scale factor.
