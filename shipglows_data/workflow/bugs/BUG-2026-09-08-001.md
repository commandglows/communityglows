# Login errors expose an opaque provider exception

## Reproduction and cause

Signing in with an email without a password account in the EU production backend
returned InvalidAccountId internally. The production client received only a
generic Convex Server Error, which LoginView displayed verbatim. This is separate
from the repaired CommandGlows bridge configuration.

## Repair

Use localized recovery messages for sign-in, registration, connectivity, rate
limits and post-authentication synchronization. Never show raw provider errors or
claim a generic server failure proves that an account is missing. Explicit invalid
account and password errors share the same message. Announce the error as an alert.

## Fix attempts

2026-09-08: presentation mapping and French/English copy implemented. Four new
regression tests plus ten existing auth-client tests pass. Windows release build
passed with the verified Doppler production configuration. The official Windows
Local shortcut points to generation 20260908T091407224Z-ec8bf6c4429b. The current
user window was preserved; rendered retest remains pending after restart.
Existing unrelated working-tree changes were preserved. No commit, push or CI
release was performed.

## Access acceptance

With the user's own production account: create it if needed, sign in, confirm the
protected workspace opens, then restart and verify session persistence. No password
or production session should be copied into this record. This acceptance is separate
from proving the error message and does not follow from build success.
