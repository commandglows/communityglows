# BUG-2026-09-05-001 — Redemption feedback

## Summary

Lifetime-code buyers must see success only after the redemption response is active and a fresh access check confirms active lifetime access without error. Scope is client feedback; no backend entitlement, payment, auth policy, or storage change.

## Reproduction

1. Instantiate the billing composable as a signed-in test account with inactive access.
2. Return an inactive redemption response; alternatively return active redemption followed by a failed access check or trial-only snapshot.
3. Submit a synthetic code through `redeemCode`.

Expected: no success, actionable existing error key, and no successful result that would clear the entered code. Observed before repair: `billing.redeem_success` in all three failure scenarios. In BillingAccessPanel this success also masks an error because success renders first.
