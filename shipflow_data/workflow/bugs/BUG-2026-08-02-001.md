# Bug Record: BUG-2026-08-02-001

## Summary

- Title: Windows network clicks do not open a child WebView
- Current status: `fixed-pending-verify`
- Severity: `high`
- Owner: `106-sg-fix`
- Next step: build and manually retest the asynchronous Windows child-WebView creation path

## Reproduction

- Preconditions:
  - Install the current `windows-latest` SocialGlowz installer.
  - Complete onboarding so the desktop sidebar is visible.
- Steps:
  1. Launch SocialGlowz on Windows.
  2. Click any built-in network in the left sidebar.
  3. Observe the central content area.

## Expected Behavior

- The selected network opens visibly in the central native WebView area.

## Observed Behavior

- The click changes application state, but no network content becomes visible.

## Evidence

- `src/ui/setup/pages/SocialGlowz/App.vue`: `NetworkWebviewHost` mounts only when `activeUrl` becomes truthy.
- `src/ui/setup/pages/SocialGlowz/components/NetworkWebviewHost.vue`: an immediate watcher opens the native WebView during component setup.
- `src/ui/setup/pages/SocialGlowz/composables/useNetworkWebview.ts`: initial IPC dimensions come from `useElementBounding`, whose pre-mount values are zero.
- `src-tauri/src/lib.rs`: desktop `open_webview` applies the supplied dimensions; Android ignores them.
